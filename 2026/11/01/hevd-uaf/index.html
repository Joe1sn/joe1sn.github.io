漏洞点分析

主要涉及到的函数如下

AllocateUaFObjectNonPagedPool，主要是分配内核堆，简称函数A

其中在g_UseAfterFreeObjectNonPagedPool（即PoolWithTag）设置了回调函数UaFObjectCallbackNonPagedPool

UseUaFObjectNonPagedPool，根据全局变量找到这个堆块，然后调用其回调函数，简称函数B

FreeUaFObjectNonPagedPool：释放我们申请的堆块，简称函数C

并且释放后没有将g_UseAfterFreeObjectNonPagedPool指针置为0，造成可以释放后重用

一般情况下使用方式是A->B->C，但是可以A->C->B就构成了 Use after Free（释放后使用）

在C->B这个过程中如果能让我们的申请到这个区块，这样我们就能改写回调函数的内容从而实现漏洞利用

PoC编写

先写功能点吧，经典的CTF pwn步骤

现在我们的目标首先是将回调函数覆写（例如AAAAAAAAAA），先造成蓝屏

注意到AllocateUaFObjectNonPagedPool申请的chunk大小是0x60，实际分配大小应该是0x70。

这里我们无法精确的布置堆风水，所以顺着之前文章在内核池溢出的堆喷射进行攻击，这里尝试使用named pipe作为内核对象

不过HEVD提供了更简单版本的AllocateFakeObjectNonPagedPool函数

能帮我们在内核创建一个大小为0x70的chunk（0x58大小对齐=0x60+0x10_head = 0x70）

我最开始以为不需要对占用的chunk做特殊的限制直接全部覆写为C就能出发DSOD，然后调试发现最后Use会报错，

我们用0x4343434343434343覆写后：

然后报错

因为64 位模式下，虽然寄存器是 64 位，但实际虚拟地址只有 48 位（4 级页表）。一个地址要"合法"（canonical），必须满足：

bit 63:48 必须等于 bit 47 的符号扩展（即全 0 或全 1）

这里借鉴了[1]的地址改为0xdeadc0de即可满足

得到PoC

我一般运行两次就会BSOD

Exp编写

参考之前CVE-2023-21768的打法，使用VirtualAllocEx在申请合法内存填入shellcode然后执行，这里使用的Shellcode和之前栈溢出的一致，并且依旧需要进行ROP（绕过SMEP），这段可以参考StackOverflow中的ROP链，但是首先要做的是栈迁移。我学习了[1]中的栈迁移打法

首先找到ROP

然后利用windows API VirtualLock

将进程的虚拟地址空间的指定区域锁定到物理内存中，确保后续访问该区域不会产生页面错误。

这里依旧有一些小问题

在执行栈迁移（pivot）gadget 时，程序发生了崩溃。这类问题调试起来可能比较棘手，原因在于涉及两个方面：首先，我们需要在 gadget 前后预留一定的空间，以便内核能够对其进行读写操作；其次，必须确保栈内存已被调入物理内存（即已完成分页），因为在此阶段无法处理缺页异常（此时我们仍处于内核模式）。我们对概念验证（PoC）代码进行了更新：在缓冲区前额外分配了 0x1000 字节的空间，并使用 VirtualLock 函数强制将相关内存调入物理内存。

需要注意的是由于使用了栈迁移，这里暂时只能使用换页结束的shellcode。
